# Расширенная проверка качества модели

`ml assess` воспроизводит сохранённый временной эксперимент и дополняет его пользовательскими метриками, парными bootstrap-интервалами и сегментной диагностикой. Это исследовательская offline-команда: она не меняет .env, рабочую БД и serving-артефакт, не обращается к TMDB и не подбирает новые параметры.

## Запуск

```sh
python -m pip install -c requirements.lock -e ".[dev,ml,analysis]"
python -m ml assess \
  --dataset data/movielens/prepared-32m-v1 \
  --training-run artifacts/recommendations/movielens-32m-top30-v1 \
  --output artifacts/evaluation/movielens-32m-top30-quality-v1 \
  --resamples 2000 --bootstrap-seed 2026
```

Поддерживается подготовленный дисковый формат 2. --training-run указывает на исходный запуск с metrics.json и model/manifest.json. --block-size управляет размером блоков при восстановлении модели (по умолчанию 128). Выходной каталог должен быть новым; существующий результат команда не перезаписывает.

Результаты и графики сохраняются в artifacts, а не в docs. Отдельный отчёт по лабораторным этой командой не создаётся.

## Независимость проверки

Финальная модель сервиса обучена на всей истории, поэтому использовать её для оценки на прежнем test нельзя. Assess заново строит только тестовую копию на train + validation, строго раньше тестовой временной границы. Параметры и выбранная стратегия берутся из сохранённого эксперимента; новый поиск не выполняется. Тестовая копия не заменяет рабочий артефакт и не сохраняется как новая serving-версия.

Перед расчётом проверяются:

- SHA-256 исходных метрик и manifest подготовленных данных;
- совпадение параметров со serving-manifest;
- границы времени и размеры train/validation/test;
- исходные max_users и seed, SHA-256 выбранных ID пользователей;
- число оценённых пользователей и совпадение итоговых Precision/Recall/NDCG с ранее сохранёнными значениями (абсолютный допуск 1e-10).

Несовпадение завершает команду ошибкой. Результат публикуется только после успешных вычислений и построения графиков. Это диагностическое продолжение зафиксированного эксперимента, а не новый независимый тест после изменения модели. По этим данным нельзя задним числом перенастроить параметры и сохранить прежнее утверждение о независимости test.

## Пользовательские метрики

Для каждого выбранного пользователя строятся top-k от popularity и от ранее выбранной модели. Оба метода получают одну историю и одинаковый набор кандидатов — весь доступный до test каталог без уже оценённых фильмов. Положительная цель — отложенная оценка ≥ 4. Неизвестные модели положительные цели остаются промахами; фильмы без отложенной оценки не объявляются отрицательными предпочтениями пользователя.

Сохраняются Precision@k, Recall@k и NDCG@k каждого пользователя, фактическая стратегия (включая fallback), ранги рекомендаций и целевые фильмы. Итоговые оценки — macro-средние по пользователям. score модели не интерпретируется как вероятность или прогноз личной оценки.

Пользователи без истории до test не входят в персональную оценку; их количество сохранено отдельно. Проверка не устанавливает качество для полностью нового профиля приложения.

## Парный bootstrap

Единица повторной выборки — пользователь. Для каждой метрики берутся пары значений popularity/selected на одних ID. На каждом из 2000 повторов ID выбираются с возвращением, причём обе стратегии используют одинаковые индексы. Вычисляются средние каждой стратегии и средняя парная разность selected − popularity. Границы 95 % percentile-интервала — квантили 2,5 и 97,5 % bootstrap-распределения.

Парная разность оценивается непосредственно, а не как вычитание границ двух независимых интервалов. interval_excludes_zero показывает, исключает ли её интервал ноль; это не вычисленный p-value. --bootstrap-seed влияет только на повторные выборки, а исходные пользователи восстанавливаются по seed оригинального эксперимента.

Интервалы условны относительно фиксированной модели и наблюдаемой когорты. Они не учитывают вариацию повторного обучения, ошибки источника, изменение интересов во времени или качество на другой аудитории. Нулевой интервал при отсутствии попаданий не доказывает нулевую ошибку на всей популяции. Сегментные интервалы исследовательские, без поправки на множественные сравнения.

## Группы пользователей

Группы определяются по числу всех доступных оценок до тестовой границы: 1–19, 20–99, 100–499, 500+. Для каждой группы повторяется парная проверка на её пользователях. n на графике — число пользователей, не число оценок. При n < 30 выставляется small_group=true; при отсутствии наблюдений значения не выдумываются.

Разница средних между группами не показывает причинное влияние длины истории: состав пользователей и их отложенные цели различается. Основное сравнение — между двумя алгоритмами внутри одной группы.

## Группы целевых фильмов

Популярность определяется исключительно числом оценок в истории до test, без использования полной истории из EDA или будущих оценок. Учитываются все прошлые оценки, не только положительные и не только ограничение последних 100 из обучения сходства.

| Группа | Оценок в истории до test |
| --- | --- |
| unseen | 0, фильм отсутствует в обучающем каталоге |
| tail_1-49 | 1–49 |
| middle_50-999 | 50–999 |
| head_1000+ | 1000 и более |

Для каждого пользователя исходный top-k остаётся неизменным. Ограничивается только множество положительных целей соответствующей группой. В macro-оценку группы входят пользователи хотя бы с одной такой целью; один пользователь может входить в несколько групп. Поэтому размеры групп нельзя складывать как непересекающиеся пользовательские когорты.

Сегментный recall показывает, какая доля положительных целей данной группы найдена исходным top-k. Сегментный NDCG использует идеальный DCG по этим целям; позиции рекомендаций не сжимаются. Это не оценка рекомендаций после фильтра «показывать только редкие фильмы». Для unseen у чистой collaborative-модели попадания структурно невозможны; эту задачу должен решать другой источник гибрида.

## Файлы результата

| Файл | Содержание |
| --- | --- |
| summary.json | Общие и сегментные средние, интервалы и парные разности, протокол и ограничения |
| intervals.csv | Плоская таблица mean/low/high для overall, истории и популярности целей |
| per_user.csv | Метрики обеих стратегий каждого пользователя |
| per_item_group.csv | Метрики по ограниченным множествам целей, без изменения top-k |
| cohort.csv | ID MovieLens, длина истории, число целей и известных истории фильмов |
| targets.csv | Положительные цели, историческая поддержка и группа фильма |
| recommendations.csv | Исходные top-k: метод, позиция, TMDB ID и признак попадания |
| manifest.json | Суммы входных manifest/metrics, версии библиотек и контрольные суммы результатов |

ID относятся только к анонимным пользователям MovieLens. Графики доступны отдельно в PNG (180 dpi) и SVG:

- 01_overall_intervals — общие метрики и интервалы;
- 02_history_segments — NDCG по длине истории;
- 03_item_segments — Recall/NDCG по группам целей;
- 04_paired_differences — парные разности модели и популярности.

Эти материалы оценивают только сохранённую оценочную модель и её fallback. Они не доказывают качество content-источника или полного гибрида. Проверка гибридной выдачи выполняется отдельным следующим этапом.
