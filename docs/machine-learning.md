# Обучение рекомендательной модели

## Данные

Основной датасет — MovieLens 32M, опубликованный GroupLens в 2024 году, с оценками до 12 октября 2023 года. Он содержит анонимные оценки, фильмы и соответствия MovieLens ↔ TMDB. Источник: https://grouplens.org/datasets/movielens/32m/; описание формата и лицензии: https://files.grouplens.org/datasets/movielens/ml-32m-README.html.

Профили приложения не сопоставляются с пользователями датасета. Сериалы не участвуют в оценочной модели. Фильмы вне датасета, включая более новые, могут попадать в гибридную выдачу через TMDB content-источник.

Исходный ZIP и подготовленные данные находятся в data/movielens/, результаты — в artifacts/recommendations/<version>/. Эти каталоги исключены из Git. Рабочая SQLite-БД не заполняется учебными фильмами и оценками. Артефакт модели не содержит историй отдельных пользователей; числовые метрики и сводка запуска сохраняются в artifacts, а не в docs.

Данные предназначены для исследовательского использования; коммерческое применение требует разрешения GroupLens. Исходный README сохраняется рядом с подготовленными данными и моделью. При публикации результатов следует указать: F. Maxwell Harper and Joseph A. Konstan. 2015. *The MovieLens Datasets: History and Context*. DOI: 10.1145/2827872.

## Воспроизводимый запуск

В корне бэкенда, в активированном виртуальном окружении:

```sh
python -m pip install -c requirements.lock -e ".[dev,ml]"
python -m ml download --source 32m
python -m ml prepare --source 32m
python -m ml train \
  --dataset data/movielens/prepared-32m-v1 \
  --output artifacts/recommendations/movielens-32m-top30-v1 \
  --evaluation-users 2000 --block-size 128
```

32m — источник по умолчанию для CLI. Архив сохраняется как data/movielens/ml-32m.zip, подготовленная версия — prepared-32m-v1. Параметры --archive, --directory и --output позволяют явно выбрать пути. Существующие подготовленные каталоги и результаты обучения не перезаписываются: для нового запуска укажите новое имя.

Архив проверяется по зафиксированному SHA-256:

```text
e4a68655d7386b8f95f2f2424b2ff975dfdd15ffd59e0d864a14dca43e99d6ee
```

Пин получен после проверки CSV по опубликованным GroupLens MD5. Несовпадение SHA-256 завершает команду ошибкой; другая версия источника требует явного обновления и проверки. Неудачная загрузка не заменяет архив; подготовка публикует каталог только после успешного завершения.

## Потоковая подготовка 32M

movies.csv и links.csv малы и загружаются в память. ratings.csv читается последовательно из ZIP пакетами не более 100 000 записей. Проверяются заголовки, идентичности, ссылки на фильмы, положительные timestamps, оценки 0,5–5 с шагом 0,5. Строгое возрастание пары (userId, movieId), предусмотренное форматом GroupLens, проверяется для каждой записи: это одновременно исключает дубликаты без хранения 32 млн пар в set.

Фильмы без TMDB ID и все неоднозначные соответствия исключаются вместе с их оценками. Счётчики исключений записываются в manifest.json. Подготовка не обращается к TMDB и рабочей БД.

Результат формата 2:

- movies.json: MovieLens ID, TMDB ID, название, жанры;
- ratings.bin: упакованные записи little-endian по 20 байт — int32 user, int32 movie, float32 rating, int64 timestamp;
- SOURCE_README.txt: описание и условия источника;
- manifest.json: источник, контрольные суммы, размер, количество записей и временной диапазон.

При чтении проверяются суммы и размер ratings.bin. DiskRatings использует read-only memory mapping, а временные подмножества — массивы индексов. Миллионы Python-объектов Observation не создаются. Файл сохраняет исходный порядок user/movie; временные границы определяются по timestamp независимо от этого порядка.

## Оценочная модель

Popularity ранжирует фильмы по числу оценок ≥ 4 в доступной обучающей части. Это статистика MovieLens, не TMDB popularity.

Item-based collaborative filtering строит бинарную разреженную матрицу положительных оценок (rating ≥ 4). Для вычисления сходства в 32M используются до 100 самых поздних положительных оценок каждого пользователя внутри текущей обучающей части. При равном времени приоритет определяется MovieLens ID. Это ограничивает влияние очень активных пользователей и вычислительные затраты. Популярность и исключение просмотренного используют всю доступную историю, а не только эти 100 оценок.

Cosine similarity между фильмами умножается на `support / (support + shrinkage)`, где support — число пользователей, положительно оценивших оба фильма. Пары с support < 3 исключаются, диагональ равна нулю. Полная матрица movie × movie не строится: cooccurrence вычисляется блоками по 128 исходных фильмов; для каждого сохраняются только лучшие соседи. Сходства и sparse-индексы хранятся в float32/int32.

Для нового профиля балл кандидата — сумма `similarity(seed, candidate) × (rating(seed) − 3)` по известным оценённым фильмам. Низкие оценки уменьшают балл, тройка нейтральна. Все оценённые фильмы исключаются независимо от значения. При отсутствии известных положительных оценок или кандидатов с положительным баллом используется popularity. Вычисление профиля выполняется разреженным умножением, а не циклом SQL или HTTP-запросов.

## Выбор параметров и проверка качества

Разбиение — глобальное временное приблизительно 70/15/15. Равные timestamps остаются в одной части: все train строго раньше validation, validation строго раньше test. Никакой пользователь не вносит будущие взаимодействия в обучающую матрицу.

Для 32M сравниваются 40 и 80 соседей при заранее заданных shrinkage=50, min_support=3, max_user_positives=100. Две версии используют один расчёт сходства; вариант 40 отбрасывает хвост ранжированных соседей. Выбор выполняется по validation NDCG@30. Если item-based не превосходит popularity, выбирается popularity.

После фиксации параметров тестовая модель обучается на train + validation и один раз измеряется на test. Затем финальная serving-модель обучается на всех подготовленных данных. Метрики test относятся к тестовой модели, а не к заново обученному финальному артефакту. Выбор по test задним числом не меняется.

Для каждой части оцениваются пользователи с предыдущей историей и отложенными положительными оценками ≥ 4. При числе таких пользователей выше --evaluation-users берётся воспроизводимая выборка без возвращения (seed=2026). Все стратегии одной части используют один и тот же набор пользователей. В metrics.json записываются размер доступной когорты, размер выборки, seed и SHA-256 выбранных ID. Пользователи без истории учитываются отдельно; их нельзя считать измеренной персональной выдачей.

Кандидаты — весь каталог соответствующей обучающей модели за вычетом оценённых фильмов; случайные отрицательные кандидаты не подбираются. Неизвестные модели положительные цели остаются в знаменателе как промахи. Метрики: macro Precision@30, Recall@30, NDCG@30 и охват каталога. Подсчёт рейтингов целей и неизвестных целей относится ко всей целевой части; macro-метрики — только к выбранным пользователям.

Эта проверка относится к оценочной модели, не к гибридной выдаче. Для гибрида потребуется отдельный эксперимент с зафиксированными метаданными и временными границами. Его инженерные веса нельзя считать обученными по этим метрикам. Метрики Small и 32M напрямую не сравниваются: это разные каталоги и когорты.

## Диагностическое продолжение эксперимента

`ml assess` восстанавливает тестовую копию по сохранённым параметрам, сверяет исходные метрики и создаёт парные bootstrap-интервалы и сегментные таблицы. Для проверки не используется финальная serving-модель, обученная на test. Порядок запуска и ограничения интерпретации — в [расширенной оценке](model-evaluation.md).

## Артефакт и подключение

Запуск сохраняет metrics.json, summary.json, SOURCE_README.txt и model/:

- manifest.json: версия модели и формата, параметры, источник, контрольные суммы и версии зависимостей;
- movies.json: mapping индексов, MovieLens/TMDB ID, названия и жанры;
- similarities.npz: разреженная матрица соседей;
- popularity.npy: статистика положительных оценок.

Формат serving-артефакта остаётся версией 1; модели Small совместимы, отсутствующий max_user_positives интерпретируется как 0 (без ограничения). Pickle не используется. Загрузка проверяет суммы, размер файлов и развёрнутых массивов, размерности и допустимость весов.

В .env:

```dotenv
MOVIE_RECOMMENDATION_MODEL_PATH=artifacts/recommendations/movielens-32m-top30-v1/model
```

После изменения пути перезапустите API. Успешную загрузку показывает `/ready`: model=ready. Артефакт необязателен: при его недоступности остаются content/popularity. Ограничения ресурсов и гибридная сборка описаны в [рекомендациях](recommendations.md).

Проверка артефакта без HTTP и БД (ключи — TMDB ID фильмов нового профиля):

```sh
python -m ml recommend \
  --model artifacts/recommendations/movielens-32m-top30-v1/model \
  --ratings '{"603":5,"414906":5}' --limit 10
```

Для отката укажите путь предыдущей модели Small в .env и перезапустите сервис. Старые артефакты автоматически не удаляются.

## Совместимость с Small

Небольшой датасет остаётся доступен для быстрых экспериментов:

```sh
python -m ml download --source small
python -m ml prepare --source small
python -m ml train --dataset data/movielens/prepared-v1 --output artifacts/recommendations/small-experiment
```

Подготовленный формат 1 (movies.json, ratings.csv, SOURCE_README.txt, manifest.json) читается без преобразования. Для Small сохраняются прежняя сетка neighbors={40,80}/shrinkage={10,50}, min_support=2 и проверка всех подходящих пользователей. Обучение также использует блочный расчёт сходства; ограничение 100 положительных оценок для Small по умолчанию не применяется.

## Текущий артефакт

Измеренные результаты movielens-32m-top30-v1 и границы их интерпретации собраны в [карточке модели](model-card.md).

Размер ранжирования задаётся `ml train --k 30` (по умолчанию 30; допустимо 1–100). Один k используется при выборе по validation и измерении на test; assess берёт его из сохранённого metrics.json. Прежний эксперимент top-10 остаётся отдельным архивным запуском.
