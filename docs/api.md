# HTTP API

Базовый адрес локального сервиса: `http://127.0.0.1:8000`. Интерактивная схема доступна по `/docs`, машинная схема — по `/openapi.json`.

## Текущее покрытие

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /health | Работоспособность процесса без обращения к БД |
| GET | /ready | Готовность БД и схемы |
| GET | /api/v1/discovery/movies | Поиск и популярные подборки TMDB без сохранения |
| GET | /api/v1/discovery/movies/{media_type}/{tmdb_id} | Просмотр карточки TMDB без сохранения |
| GET | /api/v1/movies | Поиск по локальному каталогу сохранённых записей |
| GET | /api/v1/movies/{movie_id} | Карточка по внутреннему UUID |
| GET | /api/v1/movies/by-tmdb/{media_type}/{tmdb_id} | Разрешение внешнего ID без импорта |
| POST | /api/v1/catalog/import | Импорт страницы из TMDB |
| POST | /api/v1/catalog/import/{media_type}/{tmdb_id} | Импорт отдельного фильма или сериала |
| POST | /api/v1/profiles | Создать профиль |
| GET | /api/v1/profiles | Список профилей |
| GET | /api/v1/profiles/{profile_id} | Получить профиль по UUID |

Авторизация пока отсутствует. Методы профилей предназначены для локального приложения с общим списком профилей. Оценки и избранное разделены по profile_id, но это не проверка права доступа. Рекомендации доступны при настройке обученного артефакта. Импорт каталога также предназначен только для локального использования до внедрения авторизации.

## Создание профиля

`POST /api/v1/profiles`, Content-Type: application/json.

```json
{"name": "Арсений"}
```

Имя — строка из 1–80 символов после удаления пробелов по краям. Неизвестные поля запрещены. Одинаковые имена допустимы.

Ответ: HTTP 201, заголовок `Location: /api/v1/profiles/{id}`.

```json
{
  "id": "b6f24735-33a6-44d4-af52-cf96e75f5968",
  "name": "Арсений",
  "created_at": "2026-11-08T12:00:00Z"
}
```

Идентификатор генерирует сервер. Время возвращается в UTC. Данные записываются в одной транзакции; ответ об успехе возвращается после commit.

## Чтение профиля

`GET /api/v1/profiles/{profile_id}` возвращает HTTP 200 и объект того же формата. Некорректный UUID даёт 422; отсутствующий профиль — 404.

## Список профилей

`GET /api/v1/profiles?limit=50&offset=0`.

- limit: 1–100, по умолчанию 50.
- offset: неотрицательное число, по умолчанию 0.
- Сортировка: время создания, затем UUID, по возрастанию.

```json
{"items": [], "limit": 50, "offset": 0}
```

`items` содержит объекты профилей. Список ограничивается пагинацией; общее количество записей не возвращается.

## Готовность

`GET /health` возвращает HTTP 200 и `{"status":"ok"}` независимо от схемы БД.

`GET /ready` возвращает HTTP 200:

```json
{"status":"ready","database":"ready","model":"not_configured"}
```

Если БД недоступна, ревизия Alembic не соответствует приложению или отсутствует требуемая таблица, ответ имеет HTTP 503:

```json
{"status":"not_ready","database":"unavailable","model":"not_configured"}
```

Если артефакт не настроен, model=not_configured не блокирует готовность остального API. При успешной загрузке model=ready. Если путь настроен, но артефакт недоступен или некорректен, model=unavailable. HTTP-готовность определяется БД и схемой: без модели доступны остальные источники рекомендаций.

## Ошибки

Доменные ошибки и ошибки БД имеют формат:

```json
{"error":{"code":"profile_not_found","message":"Profile not found"}}
```

| HTTP | code | Значение |
| --- | --- | --- |
| 404 | profile_not_found | Профиль не существует |
| 404 | movie_not_found | Фильм не найден в локальном каталоге или в TMDB |
| 502 | metadata_unavailable | TMDB недоступен или вернул некорректные данные |
| 503 | catalog_not_configured | Не задан ключ TMDB |
| 422 | invalid_profile_name | Нарушено доменное ограничение имени |
| 503 | recommendation_unavailable | Нет доступного источника рекомендаций |
| 503 | database_unavailable | Операцию с БД не удалось выполнить |

Ошибки валидации HTTP-запроса имеют стандартный формат FastAPI с полем `detail` и статусом 422. Ответы об ошибках БД не содержат SQL, параметры подключения или traceback.

## CORS

Список разрешённых адресов фронтенда задаётся JSON-массивом в `MOVIE_CORS_ORIGINS`. Разрешены методы GET, POST, PUT и DELETE, заголовок Content-Type. Передача credentials не включена. CORS не является механизмом авторизации.

## Каталог

`GET /api/v1/movies` читает только импортированные записи из локальной БД и не обращается к TMDB.

| Параметр | Значение |
| --- | --- |
| q | Часть русского или оригинального названия, до 150 символов |
| media_type | movie (по умолчанию) или tv |
| genre_id | Положительный ID жанра TMDB в контексте media_type; 16 — анимация |
| page | Номер локальной страницы, от 1 |
| page_size | Размер страницы 1–100, по умолчанию 20 |

Поиск не зависит от регистра. Символы `%` и `_` трактуются буквально. Сортировка: popularity по убыванию, затем UUID по возрастанию. При отсутствии записей items пустой, total_results и total_pages равны 0. Страница за пределами каталога возвращает пустой items и существующее количество совпадений.

```json
{"items": [], "page": 1, "page_size": 20, "total_results": 0, "total_pages": 0}
```

`GET /api/v1/movies/{movie_id}` принимает внутренний UUID, а не TMDB ID. Объект фильма содержит:

```json
{
  "id": "c9b6a844-febe-4bd2-9687-0fab1b16e871",
  "tmdb_id": 354912,
  "media_type": "movie",
  "title": "Тайна Коко",
  "original_title": "Coco",
  "overview": "Описание фильма",
  "poster_path": null,
  "backdrop_path": null,
  "release_date": "2017-10-27",
  "vote_average": 8.2,
  "vote_count": 100,
  "popularity": 20.0,
  "genres": [{"tmdb_id": 16, "name": "Мультфильм"}],
  "updated_at": "2026-11-08T12:00:00Z",
  "movielens_id": null
}
```

Изображения заданы относительными путями TMDB либо null; дата выхода может быть null. Поля vote_average и popularity относятся к TMDB. Это не личная оценка пользователя и не результат рекомендательной модели.

## Импорт из TMDB

`POST /api/v1/catalog/import`, ответ HTTP 200. Команда получает одну страницу источника, сохраняет её в одной транзакции и возвращает импортированные объекты с внутренними UUID.

```json
{"media_type":"movie","q":"","genre_id":16,"page":1}
```

Поля необязательны: media_type по умолчанию movie, q — пустая строка, genre_id — null, page — 1. Диапазон page: 1–500. Неизвестные поля запрещены.

- Без q и жанра импортируется страница популярных фильмов или сериалов.
- С genre_id используется TMDB Discover, сортировка по популярности.
- С q используется поиск TMDB. При одновременном genre_id фильтруется только полученная страница: source_total_results и source_total_pages описывают исходный поиск TMDB до фильтра жанра. Количество импортированных объектов указано отдельно.

```json
{"items": [], "page": 1, "imported_count": 0, "source_total_results": 0, "source_total_pages": 0}
```

Повторный импорт обновляет метаданные и жанры, сохраняя UUID и ранее установленный movielens_id. Дубликаты внутри страницы объединяются по media_type и tmdb_id. Команда не обходит автоматически все страницы и не удаляет ранее сохранённые фильмы, отсутствующие в новой подборке.

`POST /api/v1/catalog/import/{media_type}/{tmdb_id}` импортирует отдельную карточку. Например, `/api/v1/catalog/import/movie/354912`. Тело не требуется. Ответ HTTP 200 — объект фильма того же формата, что у GET карточки. Для сериалов используйте media_type=tv.

Данные импортируются с русской локализацией. HTTP-таймаут настраивается через MOVIE_TMDB_TIMEOUT. Ключ MOVIE_TMDB_API_KEY хранится только в окружении бэкенда. При сбое источника сохранённый каталог остаётся доступным.

## Разрешение TMDB ID

`GET /api/v1/movies/by-tmdb/{media_type}/{tmdb_id}` возвращает уже сохранённую карточку в том же формате, что GET по UUID. Отсутствующий фильм даёт 404. Этот метод не обращается к TMDB и не импортирует данные; он используется для совместимости ранее сохранённых ссылок.

## Внешний поиск и просмотр

`GET /api/v1/discovery/movies?q=&media_type=movie&genre_id=&page=1` обращается к TMDB через кэш бэкенда, без записи в БД. Без q возвращается популярная подборка, с жанром — TMDB Discover, с q — поиск. Параметры q до 150 символов, media_type movie или tv, genre_id — положительный ID, page — 1–500.

Ответ содержит items, page, total_pages и total_results. Формат items соответствует метаданным фильма, но id=null: внутренний UUID ещё не выделен. Внешняя идентичность — media_type и tmdb_id. updated_at и movielens_id в preview отсутствуют.

При одновременном q и genre_id фильтр жанра применяется к текущей странице TMDB. total_results=null: количество всех отфильтрованных совпадений неизвестно. total_pages описывает навигацию по исходному поиску и ограничено 500 страницами. Пустая отфильтрованная страница не означает отсутствие совпадений на последующих страницах.

`GET /api/v1/discovery/movies/{media_type}/{tmdb_id}` возвращает preview отдельной карточки. Просмотр не импортирует фильм и не требует существования локальной записи.

Действие пользователя над внешней карточкой отправляется непосредственно в метод библиотеки. Бэкенд сам находит сохранённый фильм либо загружает отсутствующий и сохраняет его вместе с действием. Отдельный импорт со стороны фронтенда не требуется.

POST импорта страницы — служебная операция, не часть пользовательского поиска. Методы локального каталога и импорта сохранены для совместимости и подготовки ML-данных.

## Библиотека профиля

Все пути ниже начинаются с `/api/v1/profiles/{profile_id}`. Несуществующий профиль возвращает 404. UUID профиля пока не подтверждает право доступа.

| Метод | Путь | Тело и ответ |
| --- | --- | --- |
| GET | /library | 200: `{ "favorites": [], "ratings": [] }`, полный снимок без пагинации |
| PUT | /favorites | `{ "media_type": "movie", "tmdb_id": 603 }`, 200: запись избранного |
| PUT | /favorites/{movie_id} | Без тела, 200: запись избранного |
| DELETE | /favorites/{movie_id} | 204, в том числе при отсутствии связи |
| PUT | /ratings | `{ "media_type": "movie", "tmdb_id": 603, "value": 5 }`, 200: оценка |
| PUT | /ratings/{movie_id} | `{ "value": 4 }`, 200: оценка |
| DELETE | /ratings/{movie_id} | 204, в том числе при отсутствии связи |
| POST | /library/import | Пакет прежней коллекции, 200: `{ "processed": 1 }` |

`movie_id` — UUID сохранённой карточки. Для внешнего ID media_type обязателен (movie или tv), tmdb_id — строго положительное целое. Значение оценки — строго целое 1–5; строки, дроби и bool дают 422. Неизвестные поля тела запрещены.

Запись избранного содержит `movie` (полную сохранённую карточку) и `created_at`; запись оценки — `movie`, `value`, `updated_at`. Даты возвращаются в UTC. Повторный PUT избранного сохраняет исходную дату, PUT оценки заменяет значение и дату. Коллекции отсортированы по дате по убыванию, затем UUID фильма. Избранное и оценка независимы; удаление действия не удаляет фильм.

При внешнем PUT недостающая карточка загружается из TMDB до записи. Фильм и действие сохраняются атомарно: ошибка не оставляет отдельно импортированного фильма. Для уже сохранённого фильма, чтения коллекции и удаления TMDB не нужен.

### Перенос браузерной коллекции

```json
{"entries":[{"media_type":"movie","tmdb_id":603,"favorite":true,"rating":5,"rated_at":"2026-11-08T12:00:00Z"}]}
```

В пакете 1–20 записей. У каждой должна быть хотя бы одна операция: favorite=true либо rating. rated_at необязателен; при указании требует часового пояса. Пакет сохраняется в одной транзакции. processed — число уникальных внешних идентичностей после объединения дубликатов, а не количество новых строк БД. Повторный перенос не меняет существующие серверные оценки и дату избранного. Атомарность действует внутри одного запроса; несколько пакетов — отдельные транзакции.

## Рекомендации

`GET /api/v1/profiles/{profile_id}/recommendations?limit=30`, limit: 1–50 для обычного режима (по умолчанию API — 10). Несуществующий профиль — 404; недоступность всех подходящих источников — 503. Запрос не обучает модель и не сохраняет фильмы в БД.

```json
{
  "items": [],
  "strategy": "popularity",
  "model_version": null,
  "known_ratings": 0,
  "movie_ratings": 0,
  "fallback_reason": "model_not_configured",
  "metadata_partial": false,
  "sources": [
    {"source": "collaborative", "status": "not_configured"},
    {"source": "content", "status": "ready"},
    {"source": "popularity", "status": "ready"}
  ],
  "degraded": false
}
```

Элемент items содержит movie (preview с id=null), score (внутренний балл слияния рангов) и sources — список источников этого фильма. Score не является вероятностью или прогнозом оценки. strategy — item_knn, content, hybrid или popularity. model_version допускает null при отсутствии загруженного артефакта. known_ratings относится только к оценочной модели; movie_ratings — ко всем оценкам фильмов выбранного профиля. Сериалы не учитываются, все оценённые фильмы исключаются из каждого источника и запасной выдачи.

Список sources отражает состояние использованных источников: collaborative, content и при необходимости popularity. Статусы — not_configured, ready, partial, unavailable. degraded=true означает, что часть источников дала ошибку, была доступна частично или превысила срок ожидания. Отсутствие необязательного ML-артефакта само по себе не считается сбоем.

fallback_reason — null для персональной подборки; для базовой выдачи возможны no_known_positive_ratings, no_positive_candidates, baseline_selected, model_not_configured, model_unavailable. Результат может содержать меньше limit элементов, если ограниченный пул кандидатов исчерпан.

Подбор по содержанию может рекомендовать фильмы вне каталога ML, в том числе новые. Это эвристика по жанрам и совпадениям слов описания, а не обученная текстовая модель. При сбое TMDB оценочная модель продолжает работать: недостающие preview используют названия из артефакта без постеров, metadata_partial=true. Подробнее — [гибридные рекомендации](recommendations.md).

## Случайные рекомендации

`GET /api/v1/profiles/{profile_id}/recommendations?limit=10&mode=surprise`

Параметр `mode`: `personalized` (по умолчанию) или `surprise`. Необязательный `seed` — целое от 0 до 4294967295, используется только режимом `surprise`; без него генерируется новый seed. `limit` — 1–50 для personalized и 1–20 для surprise. Неверные параметры возвращают 422, отсутствующий профиль — 404, недоступность всех источников — 503.

В обоих режимах ответ дополнен `mode`, `seed` (null для personalized), а каждый элемент — `exploratory`. Помимо обычных стратегий возможна `exploration`: случайная выдача без положительных связей в отобранных кандидатах. `sources` по-прежнему описывает источник данных: collaborative — каталог артефакта, content — TMDB. Запрос ничего не импортирует в БД. Алгоритм и ограничения описаны в [рекомендациях](recommendations.md#режим-удиви-меня).
