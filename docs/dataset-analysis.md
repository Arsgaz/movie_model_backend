# Исследование датасета

Команда `ml analyze` рассчитывает описательную статистику всего подготовленного набора и создаёт самостоятельные PNG/SVG-графики. Анализ выполняется отдельно от обучения, не меняет модель, не запрашивает TMDB и не подключается к рабочей БД. Числовые результаты и изображения сохраняются в artifacts; документация описывает запуск и методику.

## Запуск

В виртуальном окружении из корня бэкенда:

```sh
python -m pip install -c requirements.lock -e ".[dev,ml,analysis]"
python -m ml analyze \
  --dataset data/movielens/prepared-32m-v1 \
  --output artifacts/analysis/movielens-32m-eda-v1
```

`--dataset` по умолчанию указывает на подготовленный 32M. Поддерживается также формат Small: `--dataset data/movielens/prepared-v1`. `--chunk-size` задаёт число записей в одном пакете (по умолчанию 1 000 000). Существующие каталоги не перезаписываются: для повторного эксперимента выберите новое имя.

NumPy используется для вычислений, Matplotlib устанавливается дополнительным extra analysis. HTTP-сервис не импортирует модуль построения графиков и не нуждается в этом extra. Для запуска без графического окружения выбран backend Agg; кэш шрифтов размещается во временном каталоге.

## Полнота анализа и память

В расчёт входят все записи подготовленного датасета, без пользовательской или рейтинговой выборки. Файлы сначала проверяются по контрольным суммам. Для 32M чтение выполняется через read-only memory mapping, обрабатываются последовательные пакеты; не создаются ни плотная матрица пользователь × фильм, ни массив миллионов Python-объектов.

Хранятся счётчики пользователей, фильмов, десяти значений оценки, месяцев, жанров и годов. Количественные квантили оценок вычисляются точно из гистограммы, с линейной интерполяцией NumPy, без разворачивания частот обратно в 32 млн элементов. Изменение размера пакета не меняет статистику.

Уникальность пар пользователь–фильм гарантирует предыдущий этап подготовки. Analyze не создаёт повторный огромный set всех пар; он проверяет диапазоны оценок, допустимость ссылок и согласованность размеров. Высокая активность сама по себе не считается ошибкой и не приводит к удалению пользователя или фильма.

## Файлы результата

| Файл | Содержание |
| --- | --- |
| summary.json | Размеры, разреженность, квантили, средние, заполненность метаданных, границы времени и счётчики очистки |
| rating_distribution.csv | Число и доля каждого значения оценки от 0,5 до 5 |
| user_activity.csv | MovieLens user ID и количество его оценок в подготовленном наборе |
| movies.csv | MovieLens/TMDB ID, название, жанры, год, число оценок, средняя оценка и число положительных |
| monthly_ratings.csv | Число оценок, среднее и число положительных по календарным месяцам UTC |
| genres.csv | Размер жанровых групп и число относящихся к ним оценок |
| release_years.csv | Число фильмов и оценок по году выпуска из названия; пустой год означает отсутствие распознанного значения |
| concentration.csv | Доля оценок у верхних 1/5/10/20/50/100 % пользователей и фильмов |
| manifest.json | Источник, SHA-256 подготовленного manifest, размер пакета, версии библиотек и контрольные суммы результатов |

ID пользователей относятся только к анонимному датасету MovieLens, а не к профилям приложения. CSV записываются в UTF-8 и не требуют pandas для повторного использования. Каталог результата публикуется только после успешного построения всех таблиц и графиков.

## Графики

Каждая фигура сохраняется в PNG (180 dpi) и SVG:

1. `01_rating_distribution` — частоты оценок с долями.
2. `02_user_activity` — гистограмма числа оценок пользователя.
3. `03_movie_popularity` — гистограмма числа оценок фильма.
4. `04_feedback_concentration` — накопленная доля обратной связи для пользователей и фильмов.
5. `05_rating_timeline` — число и среднее оценок по месяцам UTC.
6. `06_genres` — число фильмов и оценок по жанрам.
7. `07_release_years` — число фильмов и оценок по годам выпуска.

Жанровая фигура пропускается, если в наборе нет жанров; фигура годов — если нет распознанных годов. Для основного 32M доступны все семь. Графики самостоятельны и пригодны для включения в будущие лабораторные отчёты.

## Определения и ограничения интерпретации

Плотность — `число оценок / (число пользователей × число фильмов)`, разреженность — `1 − плотность`. Рассчитываются два варианта: для всего подготовленного каталога и только фильмов с хотя бы одной оценкой. Фильмы без оценок сохраняются в статистике метаданных; в гистограмме популярности с логарифмической осью они не показываются и указаны отдельной подписью.

Для активности пользователей и оценённых фильмов сохраняются min/max, среднее, квартильные и верхние перцентили. Коэффициент Gini описывает неравномерность количества оценок, а не справедливость рекомендательной системы. В concentration.csv размер верхней группы округляется вверх; записываются как запрошенная, так и фактическая доля. Для читаемости линия концентрации использует до 1001 точек; показатели в таблицах рассчитаны по полным счётчикам.

Гистограммы активности используют геометрические интервалы и логарифмические оси. Высота столбца — число объектов в интервале, не вероятностная плотность. Незаданные оценки отсутствующих пар — это отсутствие обратной связи, не отрицательные оценки и не нули.

Положительная оценка определяется как rating ≥ 4, как в обучении и offline-проверке. Средние оценки рассчитываются по всем наблюдениям, а не только положительным. Пользователи могли иметь не менее 20 оценок в исходном MovieLens; после исключения фильмов с непригодными TMDB-связями индивидуальная история может стать короче.

Жанры не взаимоисключающие: один фильм и его оценки учитываются во всех указанных жанрах. Сумма жанровых столбцов поэтому может превышать размер каталога и число оценок. `(no genres listed)` считается отсутствием метаданных, а не отдельным жанром. Пропущенные жанры не заполняются вымышленными значениями.

Год выпуска извлекается только из конечного `(YYYY)` в названии MovieLens; он не подменяется датой оценки. Нераспознанные годы остаются неизвестными. Описания TMDB не загружаются массово: исследуются фактически доступные в MovieLens метаданные.

Временная ось основана на Unix timestamps в UTC, поэтому её граничные даты могут отличаться от текстового календарного описания источника. Граничные месяцы могут быть неполными. Месяц без оценок имеет count=0 и отсутствующее среднее; график среднего содержит разрыв, а не вымышленное значение.

Это описание всего исторического набора, не доказательство качества рекомендаций. Полные истории из EDA нельзя использовать как будущие входы временного эксперимента. Для обучения, отбора параметров и итоговой оценки сохраняется отдельный временной протокол, описанный в [машинном обучении](machine-learning.md). Числовые результаты EDA служат основанием для следующей проверки качества по группам, но не заменяют её.
