# Гибридный сервис рекомендаций

Сервис выдачи отделён от обучения и может работать без ML-артефакта. Все запросы относятся к выбранному профилю. Только оценки фильмов используются как предпочтения; избранное не преобразуется в положительную оценку, сериалы не участвуют.

## Источники

- Collaborative: необязательная item-based модель. Использует известные ей оценки и может работать без TMDB. Контракт артефакта сохраняет независимость от размера и версии исходного датасета.
- Content: эвристика по жанрам и словам из описаний. Источник кандидатов — свежие TMDB Discover-страницы; кандидаты не ограничены каталогом обучающей модели. Через ContentRecommendationProvider позже можно подключить обученную текстовую модель.
- Popularity: свежие популярные фильмы TMDB для нового профиля или заполнения свободных мест. Если TMDB недоступен, используется популярная подборка из загруженного артефакта, когда она доступна.

Content не является семантической моделью: он не распознаёт смысл разных формулировок или переводы. Его качество отдельно не измерено. Это работающий базовый источник для подготовки сервиса к следующему этапу.

## Подбор по содержанию

Используются последние 50 оценок профиля, в порядке даты изменения. Положительные оценки 4–5 задают до двух приоритетных жанров. Для каждого жанра запрашивается первая страница TMDB, а при бюджете кандидатов больше 40 — первые две страницы. При отсутствии жанров у положительных примеров используются те же страницы без жанрового фильтра.

Сходство — `0.8 × Jaccard(жанры) + 0.2 × cosine(наборы слов описания)`. Из текстов исключаются числа, короткие слова и небольшой список служебных слов. Признаки каждого фильма вычисляются один раз на запрос. Балл кандидата — сумма сходств с весом `оценка − 3`; низкие оценки уменьшают балл. Кандидаты без положительного итогового балла исключаются.

Все оценённые фильмы исключаются, включая те, что старше последних 50 оценок. Фильм может участвовать независимо от года выпуска и наличия в MovieLens, если он попал в ограниченный пул TMDB. Это не полный обход TMDB и не гарантия нахождения всех подходящих новых фильмов.

## Слияние и запасная выдача

Оценочный и content-источники работают параллельно. Их сырые баллы несопоставимы, поэтому применяется взвешенное слияние рангов: вклад источника — `weight / (60 + rank)`, rank начинается с 1. Дубликаты объединяются по TMDB ID. При равных итоговых баллах порядок определяется TMDB ID.

Если личных кандидатов меньше limit, добавляется популярный хвост без дубликатов и оценённых фильмов. Популярность не вытесняет личные результаты; её элементы имеют score=0 и sources=[popularity]. API раскрывает происхождение каждого элемента и общую стратегию. model_version=null допустим: это означает отсутствие участвующего артефакта, а не ошибку ответа.

При сбое одного источника сохраняются результаты остальных с degraded=true. Без необязательной модели сервис использует content/popularity. Если нет доступного подходящего источника, возвращается 503, а не пустая успешная коллекция. При исчерпании успешно полученного ограниченного пула допустим короткий или пустой результат.

## Ограничения ресурсов

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| MOVIE_RECOMMENDATION_CANDIDATE_LIMIT | 40 | Базовый бюджет кандидатов от источника, 20–100 |
| MOVIE_RECOMMENDATION_SOURCE_TIMEOUT | 10 | Срок ожидания источника и обогащения карточек, секунды |
| MOVIE_RECOMMENDATION_COLLABORATIVE_WEIGHT | 1 | Вес оценочного источника, >0–10 |
| MOVIE_RECOMMENDATION_CONTENT_WEIGHT | 1 | Вес content-источника, >0–10 |
| MOVIE_RECOMMENDATION_ARTIFACT_MAX_MB | 512 | Максимальный размер файлов артефакта и развёрнутых массивов |

Бюджет обычного режима — максимум из настроенного значения и удвоенного limit, с верхней границей 100. Генерация content-кандидатов делает не более четырёх запросов страниц. Популярный хвост — ещё не более трёх страниц. Обогащение отдельных карточек может делать до limit запросов; метаданные полученных страниц используются сразу. Все обращения проходят через общий ограниченный кэш TMDB. Срок ожидания источника включает ожидание очереди; источники не обходят страницы автоматически до заполнения выдачи.

Артефакт загружается однократно на процесс. Параллельные ожидания разделяют одну загрузку; отключение клиента и таймаут источника её не отменяют. Проверяются контрольные суммы потоковым чтением, размер файлов и развёрнутой NPZ, версия формата, размерности и допустимость весов. popularity.npy читается через memory mapping.

Вычисление оценочной модели выполняется вне event loop: до восьми незавершённых уникальных запросов, из них не более двух выполняются одновременно. Одинаковые наборы оценок и limit разделяют вычисление. Кэш хранит до 64 результатов в течение 30 секунд; изменение оценок меняет ключ. UUID профиля в кэш не входит, поскольку вход модели — только набор оценок, одинаковый набор даёт одинаковую выдачу.

Файловый лимит не равен полному лимиту RAM процесса: JSON, индексы, SciPy и параллельные запросы имеют накладные расходы. Для нового большого артефакта нужны отдельные измерения памяти и времени загрузки. Подготовка и обучение 32M выполняются отдельными CLI-командами, никогда в HTTP-запросе. Основной артефакт — movielens-32m-top30-v1; процедура описана в [документации обучения](machine-learning.md).

`/ready` отражает готовность БД и схемы. Поле model отдельно сообщает not_configured/ready/unavailable; неисправная необязательная модель не отключает остальные методы. Сетевую доступность TMDB `/ready` не проверяет.

## Режим «Удиви меня»

`mode=surprise` использует отдельный `SurpriseRecommender`. Обычный `mode=personalized` сохраняет ранжирование гибридного сервиса. Обучать модель заново для случайной выдачи не требуется: меняется выбор кандидатов при применении готовой модели.

ItemModel вычисляет сумму сходств с весами `оценка − 3`, исключает оценённые фильмы и кандидатов с отрицательным баллом. Случайная выборка строится по всему оставшемуся каталогу артефакта, а не по первым популярным позициям: примерно 70% кандидатов имеют положительную связь с оценками, остальные выбираются из более широкого пула. Вес редких фильмов немного выше: `1 / sqrt(1 + log(1 + popularity))`; у связанных кандидатов дополнительно учитывается нормированный балл сходства. Это не равномерная выборка каталога.

Метаданные расширяют пул независимо от MovieLens. Выбираются четыре сочетания жанра и года: два с жанром понравившихся фильмов и годом около их выпуска (±15 лет), два без ограничения жанра со случайным годом от 1900 до текущего. При отсутствии положительных жанров все сочетания свободные. Для каждого сначала читается первая страница, затем случайная страница в пределах доступных 500. Максимум — восемь запросов страниц на подборку, плюс общий кэш жанров. Ограничений по минимальному числу голосов нет. Оценки 1–2 уменьшают content-балл; кандидаты с отрицательным баллом исключаются этим источником.

После объединения по TMDB ID сервис случайно выбирает около 70% связанных и 30% исследовательских результатов, при недостатке одной группы заполняет места другой. Внутри content-пула менее популярные фильмы получают больший шанс. Коллаборативная популярность и TMDB popularity имеют разные шкалы и не сравниваются напрямую. Итоговый порядок перемешивается. Из выдачи исключены все оценённые фильмы, включая оценки за пределами последних 50; внутри подборки повторов нет. Избранное само по себе не исключается.

API возвращает `mode`, `seed` и флаг `exploratory` каждого элемента. Флаг показывает выбор из исследовательской части пула, а не гарантию отсутствия связи с предпочтениями. Стратегия `exploration` означает, что в готовой подборке нет кандидатов, помеченных как связанные. При отсутствии истории доступна случайная подборка. Популярный хвост обычного режима здесь не используется.

Без seed сервер создаёт новый 32-битный seed на каждый запрос. Фиксированный seed позволяет повторить выбор при неизменных оценках, артефакте, годе и ответах TMDB. Ответы TMDB со временем меняются, поэтому seed не является постоянным идентификатором сохранённой подборки. Между разными подборками повторы возможны; история показов не сохраняется. Ключ кэша вычислений включает seed и оценки, а количество одновременно выполняемых вычислений остаётся ограниченным.

Каталог артефакта конечен, а TMDB просматривается ограниченными страницами. Поэтому режим выходит за популярный top-N, но не гарантирует равные шансы каждому фильму TMDB. Ранее рассчитанные offline-метрики относятся к обычной item-based модели, а качество случайного гибридного режима отдельно не измерялось. Сбой одного источника оставляет доступные результаты и `degraded=true`; при недоступности обоих возвращается 503. Полученные карточки не записываются в БД.

Обычный режим в интерфейсе запрашивает до 30 фильмов вместо 10. API допускает limit до 50; пул кандидатов расширяется вместе с размером выдачи. Это верхняя граница: при недостатке подходящих кандидатов результат может быть короче. У режима surprise сохраняются собственные лимиты.
